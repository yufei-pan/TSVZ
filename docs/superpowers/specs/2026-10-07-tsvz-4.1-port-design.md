# TSVZ 4.1 — a 3.39-compatible port with spec-v1 `.tsvz` support

## Intent

TSVZ 4.0 (unreleased; `TSVZ.py` at `eb4b086`) rewrote the library around
`tsvz-spec-v1.md` and broke 3.39 files and callers. 4.1 discards that work and
ports again from 3.39 (`TSVZ_old.py`).

Two rules govern every choice below:

1. **Fault tolerance.** When input is unexpected, keep the data and keep
   going. When it is ambiguous what the right repair is, say so: emit one
   summarised warning naming the file, the problem, and what was done.
2. **3.39 compatibility unless the spec forbids it.** Every departure from
   3.39 is listed in §9.

Success means a 3.39 user upgrades and their code and `.tsv` files behave as
before, and every `.tsvz` file 4.1 writes is spec-v1 conformant.

### Decisions taken during design

| Question | Decision |
|---|---|
| How is a file's rule set chosen? | By extension. `.tsv/.csv/.nsv/.psv` (and any other extension) use 3.39 rules; `.tsvz/.csvz/.nsvz/.psvz` use spec v1. Same API for both. |
| Spec features in scope | Full single-file reader and writer, compression, in-place clear and archival scrub. Reads also replay multi-part stores and verify checksums. 4.1 writes one file only. No snapshot_store, rotation, promotion, OFD locks, or `#_write_ack_#`. |
| Append to a `.tsvz` whose tail is not `\n`-terminated | Truncate the uncommitted tail and warn, quoting it. |
| `t[missing]` on `.tsvz` | Spec-faithful: return the defaults row while `#_return_defaults_when_missing_#` is true, else `KeyError`. `.tsv` keeps `KeyError`. |
| Code structure | Two dialect classes behind one interface (approach A). |
| Rewrite features on `.tsvz` | `rewrite_on_load`, `rewrite_on_exit`, `rewrite_interval`, `rewrite()`, `mapToFile()`, `hardMapToFile()` are `.tsv` compatibility features. On `.tsvz` they warn and do nothing. Compaction of `.tsvz` is a manual archival operation: `scrubTabularFile` / CLI `scrub` only. These features may later become no-ops for `.tsv` too. |

## 2. Architecture

### 2.1 Dialects

All code that touches file bytes moves behind a dialect object chosen once per
path:

- `_LegacyDialect` — the 3.39 code, moved behind the interface without
  behaviour change except the three fixes in §3.2.
- `_SpecDialect` — spec v1.

`_dialect_for(path)` returns the spec dialect when the path's format extension
is strict (§4.1), else the legacy dialect. `TSVZed`, `TSVZedLite`, the
`*TabularFile` / `*TSV` helpers, and the CLI keep their 3.39 structure and call
the dialect for:

- reader state creation and per-line processing (3.39 `_processLine`);
- field encoding and decoding (3.39 `_sanitize` / `_unsanitize`);
- formatting a data row, a tombstone, the header line, and the defaults line;
- header verification;
- the unterminated-tail policy on append;
- whether in-place rewrite features are enabled;
- end-of-load reporting.

Each instance exposes the read-only attribute `dialect` (`'tsv'` or `'tsvz'`).

### 2.2 Reporter

A small `_Reporter(path, teeLogger)` collects tolerance events during one
operation, keyed by kind. Each kind is reported once at the end of the
operation with a count and the first line number:

```
TSVZ warning: data.tsvz: 3 lines had invalid UTF-8, replaced with U+FFFD (first at line 17)
```

Output goes to `teeLogger.teelog(msg, 'warning')` when a logger is given,
otherwise to stderr, never stdout. Reporting is always on and does not depend
on `verbose`. Messages that 3.39 already printed keep their 3.39 channel and
wording.

## 3. Legacy dialect (`.tsv`, `.csv`, `.nsv`, `.psv`, other extensions)

### 3.1 Contract

For the same sequence of API calls, 4.1 writes the same bytes as 3.39 and
returns the same read results, including 3.39's quirks:

- the header is a plain first line, verified by 3.39's substring rule;
- a lone `key` and an all-empty `key\t\t` row are deletes (a lone key is data
  when `correctColumnNum == 1`);
- escapes are `<sep>`, `<LF>`, `</sep/>`, `</LF/>`; `<` is written raw;
- an unterminated last line is read as a record;
- defaults fill present-empty cells as well as missing ones;
- `#` keys are memory-only; every `#` line except `#_defaults_#` is a comment,
  including spec marker lines;
- `mapToFile` pads changed lines with spaces;
- `rewrite_on_load` defaults to `True`.

Legacy files gain no spec features: no markers, no `<lt>`/`<#>`, no checksums,
no multi-part discovery. Siblings such as `data.tsv.1` are never treated as
parts. A 3.39 host can read any `.tsv` written by 4.1.

### 3.2 Deliberate fixes

Each case is one where 3.39 silently loses or corrupts data.

- **L1. Append after an unterminated last line.** Under the write lock, if the
  file's last byte is not `\n`, write `\n` before the batch. 3.39 glued the new
  record onto that line. The 3.39 reader already treats the line as a record,
  so this keeps reads consistent. Uncompressed files only; compressed legacy
  files keep 3.39 behaviour.
- **L2. All-empty row through the API.** `t['k'] = ['k', '', '']` (after
  defaults are applied) is treated as a delete in memory as well, matching what
  the written line means on the next load. Warn once per instance: in `.tsv`
  files an all-empty row is a delete; use `.tsvz` to store empty rows.
- **L3. `TSVZedLite` on a compressed file.** Rows are held in the index in
  memory (3.39 already allows list values for `#` keys) instead of reading
  compressed bytes as text, and writes are appended as new compressed members
  instead of raw text written into the compressed file. Warn once.

Plus **L4**: the new tolerance warnings of §7 (output only); **L5**: a
damaged compressed legacy file is read up to the damage with a warning instead
of raising; and **L6**: `mapToFile` writes the newline after a row it adds at
the end of the file (3.39 glued that row to the next one).

Appends to one path from several `TSVZed` / `TSVZedLite` / helper calls in the
same process are serialised by a per-path lock in addition to `lockf`, because
POSIX `lockf` does not exclude handles of the same process. Spec-dialect
appends open the file `O_APPEND` (`'a+b'`), as 3.39 did, so a write never lands
anywhere but the end.

## 4. Spec dialect — reading

### 4.1 Selection, delimiter, encoding

A path is parsed from the right against the spec Appendix A grammar:
`<store>.<ext>[.<hex-ordinal>][.rotated][.<codec>]`, codecs
`gz gzip bz2 bzip2 xz lzma zst zstd` (case-insensitive). If `<ext>` is
`tsvz/csvz/nsvz/psvz`, the spec dialect applies and the delimiter is `\t , \0 |`
respectively. `get_delimiter` gains the strict extensions, so `.csvz` infers
`,` (3.39 inferred tab).

An explicit `delimiter=` or a non-UTF-8 `encoding=` (compared through
`codecs.lookup`, so `utf8` and `UTF-8` are the same) that disagrees with a
strict extension is overridden by the extension and UTF-8 (§4.1/§5.1 MUST),
with a warning.

### 4.2 Store assembly (§17)

For a path naming the store (`data.tsvz`, or `data.tsvz.<codec>`):

- list directory entries `data.tsvz.<hex>[.rotated][.<codec>]`;
- skip `.rotated` parts;
- order numbered parts by `int(hex, 16)`; ties (same ordinal, different codec)
  are warned about and broken by filename;
- the unnumbered file, if present, is part 0 and precedes every numbered part;
  if both `data.tsvz` and `data.tsvz.<codec>` exist, warn and use the one named;
- the **active part** is the highest-ordinal numbered part, or the named file
  when there are no numbered parts.

Parts are replayed as one stream: marker state, defaults, and checksum
accumulators carry across part boundaries. The torn-tail rule (§4.3 step 1)
applies per part.

A path naming a numbered part (`data.tsvz.1a2b`) is read as that single file,
with a warning that it is one fragment of a store.

External-change monitoring (`TSVZed`) watches the active part's mtime and the
directory's mtime. When the directory mtime changes, the part listing is
re-read, and the store reloads only if the listing actually changed.

### 4.3 Per-record pipeline (§7)

For each part, in order:

1. **Frame.** Split raw bytes on `\n`; strip one trailing `\r`. Bytes after the
   last `\n` are discarded with a warning quoting the first 80 bytes (`repr`).
   A leading UTF-8 BOM in a part is stripped with a warning.
2. **Decode** the line as UTF-8 with `errors='replace'`; warn on replacements.
3. **Split** on the raw delimiter. Classify the raw first field `F0`:
   - matches `#_[A-Za-z0-9_-]+_#` (case-insensitive): checksum marker, official
     marker, or unrecognised marker;
   - else begins with `#`: comment;
   - else data.
4. **Checksums.** Feed the line's raw bytes (including `\r\n`) into every armed
   accumulator except the one whose marker this line is. Then arm or verify
   (§4.5).
5. **Markers.** Apply official markers (§4.4). Unrecognised and custom markers
   are ignored (named in verbose output only). Comments are ignored.
6. **Data rows.** Tombstone if and only if the raw row has no delimiter.
   Resolve the key: strip trailing space/tab if stripping is on, then decode
   tokens. An empty key ignores the row (counted, verbose only). A tombstone
   deletes the key. Otherwise resolve each written cell: strip, decode, and if
   empty and `fill_empty` is on, take the default for that column.
7. **Store** with last-wins and first-appearance order (a delete followed by a
   set re-inserts at the end, as `OrderedDict` does).

Token decoding maps `<sep>`, `<LF>`, `<lt>`, `<#>`. Any other `<…>`, including
the legacy `</sep/>` and `</LF/>`, passes through literally (§13.4).

### 4.4 Markers

| Marker | Value | Bad value |
|---|---|---|
| `#_version_#` | integer ≥ 1; empty resets to 1 | warn, keep state |
| `#_defaults_#` | fields 1.. decoded, not stripped (§10.4); lone resets to empty | — |
| `#_strip_trailing_whites_#` | bool; default true | warn, keep state |
| `#_fill_empty_with_default_#` | bool; default false | warn, keep state |
| `#_return_defaults_when_missing_#` | bool; default true | warn, keep state |
| `#_rotate_#`, `#_write_ack_#` | advisory; recorded for scrub, no effect | warn, keep state |

Booleans accept `true/false` and, silently, `yes/no/on/off/1/0`, all
case-insensitive. A declared version above 1 is applied as version 1 (§6.3)
with a warning.

The `defaults` attribute keeps the 3.39 shape `['#_defaults_#', d1, d2, …]`.
Constructor and helper `defaults=` arguments are accepted in every 3.39 form
(list, or a delimiter-joined string with or without the leading marker key) and
act as an implicit preamble: the state before the first line of the store.

### 4.5 Checksums (§15)

Supported algorithms: `crc32` (`zlib.crc32`, 8 lowercase hex digits) and every
name in `hashlib.algorithms_available` that needs no length argument. Other
algorithms, including `crc32c`, `blake3`, and `shake_*`, are inert as §15.3
allows.

The first marker for an algorithm arms its accumulator and ignores any value.
A later marker with a value verifies (hex compared case-insensitively) and
resets; with an empty value it only resets. A mismatch is a warning naming the
algorithm, the part and line, and the expected and actual digests. Data is
never dropped. Checksums are verified on full reads only, not by `lastLineOnly`.

### 4.6 Compressed parts

Compressed parts are decompressed member by member with decompressor objects
(`zlib`, `bz2`, `lzma`, and `compression.zstd` on Python 3.14+). Zero padding
between gzip members is skipped, as Python's `gzip` module does. A truncated
trailing member still yields the bytes it decompresses to, so its complete
records are kept. A corrupt member ends the part. In both cases the damage is
warned about and recorded for §5.4. A `.zst` part on an older Python is
unreadable: warn and skip that part.

### 4.7 Row shape and width

Rows are returned in the 3.39 shape `[key, v1, …]`. The store width `W` follows
3.39: the header length when a header is given and verified, else
`len(defaults)` when defaults have more than one entry, else the first row's
length.

Each row is padded to `max(W, len(row-bound defaults))`. Each absent column `j`
takes the default for `j` bound at that row's position (§14.3), or `''` beyond
the defaults. Padding to the bound defaults' width means a row always carries
every column that is not the empty string, which §5.7 relies on. Rows wider
than `W` are kept whole. The spec dialect never trims or drops a row or
cell because of its width. `strict` keeps only its 3.39 roles: a missing file
and a header mismatch are errors.

### 4.8 Header verification

4.1 writes a header as a comment: `#` followed by the delimiter-joined header,
not doubled when `header[0]` already starts with `#`. Verification takes the
first committed line of part 0 that is neither a marker nor blank (other
conformant writers may put markers before the header comment), removes one
leading `#`, and applies 3.39's substring rule. A matching header sets `W` as
in 3.39.

A first line equal to the declared header but without `#` is a data row under
the spec. It is read as data (key `id`, etc.), with a warning suggesting the
`#` prefix.

### 4.9 Tolerance summary

| Situation | Behaviour |
|---|---|
| Bytes after the last `\n` of a part | Discarded; warning quotes them |
| Invalid UTF-8 | Replaced; warning with count and first line |
| Leading BOM | Stripped; warning |
| `#_version_#` > 1 | Read as v1; warning |
| Bad marker value | Line ignored, state kept; warning |
| Unknown or custom marker | Ignored silently |
| Checksum mismatch | Warning; data kept |
| Damaged compressed stream | Read up to the damage; warning |
| Unreadable part | Skipped; warning; other parts still read |
| Delimiter or encoding argument conflicts with extension | Extension wins; warning |
| Header line without `#` | Read as data; warning |
| Numbered part opened directly | Read alone; warning |

### 4.10 `lastLineOnly` and `TSVZedLite`

`lastLineOnly` replays forward (the 3.39 compressed-file path) and returns the
last row that set a value. Backward reading cannot know the marker state in
force at a line.

`TSVZedLite` keeps integer offsets into the active part. A sorted list of
marker transitions `(offset, state)` for that part (starting from the state
carried in from earlier parts) lets a read at an offset resolve the row under
the state in force there, by bisection. When `indexes` are supplied externally,
the transition list is built by one marker-only scan on first read.

Keys whose latest record lies in an older part, or in a compressed file, are
held in the index as materialised rows, with one warning per load. On a
compressed active part, `TSVZedLite` appends new compressed members and keeps
the rows it writes in memory too (as L3). `TSVZedLite` appends its own
transitions when it writes a marker.

## 5. Spec dialect — writing

### 5.1 Encoding (§13)

`<` → `<lt>`, delimiter → `<sep>`, `\n` → `<LF>`, and a leading `#` of a data
key → `<#>`. 3.39's API normalisation still runs first: a string value is
split on the delimiter, the key is prepended if absent, and cells are
`rstrip()`ed. Values set through the API therefore never end in whitespace or
`\r`.

### 5.2 Rows, tombstones, and `#` keys

- `t[k] = v` and the stateless append helpers write exactly the given cells:
  no padding to `W`, no trimming. Present-empty cells receive the active
  default before writing (3.39 API behaviour). Memory holds the padded view
  (§4.7), which equals what a reload produces.
- `['k', '', '']` with no applicable defaults is written as `k\t\t`, a live row
  of empty cells.
- `strict=True` keeps 3.39's refusal of a value whose width differs from `W`.
  Non-strict keeps wide values whole.
- `del`, `pop`, `popitem`, and setting a lone key write a lone tombstone `k`.
- A key matching the reserved pattern `#_x_#` is a marker write:
  - `#_defaults_#` sets the defaults as in 3.39 and writes the marker with the
    given cells (no padding, and no baking of the previous defaults into its
    empty cells); deleting it writes the lone marker, which resets it;
  - other official markers are written as marker lines and update the reader
    state;
  - custom markers (`#__x__#` and unrecognised official-form names) are
    written for other tools, do not enter the dict, and are dropped by scrub
    (§19.6).
- Every other `#` key is ordinary data written as `<#>key`.

### 5.3 Creation, header, defaults

A file created with a header starts with the header comment (§4.8). Without a
header it is created empty (0 bytes).

Constructor `defaults=` behave as in 3.39: they are the read preamble, and the
file's own `#_defaults_#` lines override them. 3.39 persisted them through
`rewrite_on_load`; 4.1 persists them by appending instead. A new file gets the
`#_defaults_#` marker after its header. After loading an existing store that
never contained a `#_defaults_#` line, `TSVZed` and `TSVZedLite` append the
marker when the constructor defaults are non-empty. Without this, sparse rows
(§5.2) would read back differently when the store is opened without the same
`defaults=` argument. Stateless reads never write.

### 5.4 Appends and the uncommitted tail

Appends keep 3.39's mechanics: the append queue and background worker, one
`write()` per batch of whole `\n`-terminated records, under an exclusive
`lockf`, followed by fsync.

Before each append, under the lock:

- **Uncompressed active part.** If the last byte is not `\n`, find the last
  `\n` and truncate the file just after it (to 0 if there is none). Warn,
  quoting the removed bytes.
- **Compressed active part, `TSVZed`.** If the load recorded an uncommitted
  tail or a damaged member, repair the part under the lock before appending:
  copy its raw bytes to `<part>.damaged-<YYYYmmddTHHMMSS>`, then re-encode it in
  place with the readable content cut at the last `\n` (decompress, cut,
  recompress, write from offset 0, truncate, fsync). Every record the reader
  showed is kept byte-identical; only the uncommitted bytes and the
  unreadable remainder leave the part, and those survive in the copy. Warn,
  naming the copy. (A plain raw truncation at the last complete member would
  drop complete records that a truncated member still decompresses to, and the
  reader keeps those per §4.6.)
- **Compressed, stateless `appendLinesTabularFile`.** No check (documented).
  New records go into a new member.

A non-TSVZ writer that appends without taking the lock can have its
in-progress record truncated. This is documented as unsupported.

On `.tsvz`, `TSVZed` keeps a batch in its queue until the write succeeds. A
failed write is reported once, and retried on the next tick. Recovery is
reported once too. 3.39 popped the batch and relied on a later full rewrite
to recover, which `.tsvz` no longer does.

### 5.5 Multi-part stores

- Appends go to the active part. If it is compressed, a new member is appended.
- `clear()` and `clearTabularFile` re-read the store and append a tombstone for
  every live key to the active part (the append takes the write locks). Older
  parts are untouched. Warn once that older parts are not compacted.
- `scrubTabularFile` refuses: it returns the data read and writes nothing, with
  a warning.
- Given a path that names one numbered or rotated part, both
  `scrubTabularFile` and `clearTabularFile` refuse with a warning and write
  nothing: compacting or clearing one fragment would resurrect older values
  from the other parts.
- `move_to_end` reorders memory only, with a warning (also on single files;
  see §5.6).

### 5.6 Rewrite features on `.tsvz`

- `rewrite_on_load` defaults to a sentinel that resolves to `True` for `.tsv`
  and `False` for `.tsvz`. An explicit `True` on `.tsvz` warns.
- `rewrite_on_exit=True` and a non-zero `rewrite_interval` on `.tsvz` warn.
- Explicit calls to `rewrite()`, `mapToFile()`, and `hardMapToFile()` on
  `.tsvz` warn and return without writing (`False` / `self`, as 3.39 returns).
- The warning reads: ignored for `.tsvz`; behaviour undefined; use
  `scrubTabularFile` for archival compaction.
- The external-change reload inside `rewrite()` is kept: when another process
  changed the store, `TSVZed` commits its queue and reloads, as 3.39 does. Only
  the file rewrite is disabled. Internal calls from the append worker and
  `stopAppendThread` do not warn.
- `move_to_end` on `.tsvz` reorders memory only and warns once. It no longer
  sets `rewrite_on_exit`.

### 5.7 `scrubTabularFile` and CLI `scrub` — archival compaction (§19.8)

Single-part stores only (§5.5). The store is read without holding the write
lock — `lockf` cannot be held across the read, because the reader opens and
closes its own descriptor and POSIX releases a process's `lockf` locks when any
descriptor for the file closes — so the rewrite is guarded by an optimistic
check instead:

1. Record the part's identity `(st_ino, st_size, st_mtime_ns)`, then read the
   store.
2. Build the complete new content in memory:
   - the header comment: the file's first line if it is a plain comment,
     else the `header=` argument as a comment, else none;
   - `#_version_#\t1`;
   - non-default stateful markers (`strip` false, `fill_empty` true,
     `return_defaults_when_missing` false) and non-default advisory markers;
   - `#_defaults_#` last, if non-empty;
   - one row per live key in first-appearance order, written at its
     materialised width and extended with `''` cells up to the final defaults'
     width, so a column that read as `''` cannot pick up a final default it
     was never bound to. A row can therefore come back with extra trailing
     `''` cells, which §3.6 permits.
3. **Fidelity (§19.4).** If any row would not read back identically under the
   final marker state — a key or cell with trailing space/tab while stripping
   is on, or an empty cell whose column has a non-empty default while fill-empty is
   on — use the compensating layout instead: emit
   `#_strip_trailing_whites_#\tfalse` and `#_fill_empty_with_default_#\tfalse`
   in the preamble, write the rows, then re-emit the final values of those two
   markers after the rows.
4. Take the write locks (the per-path lock and `lockf`) and compare the part's
   current identity with the one recorded in step 1. If it changed — another
   writer committed records during the read — write nothing and start again
   from step 1. After 3 attempts that all saw a change, give up with a warning
   (scrub skipped: the store kept changing while it was being compacted;
   nothing was written).
5. If the bytes (compressed, for a compressed part) equal the current file,
   stop.
6. Otherwise, still under the locks, write from offset 0 through the existing
   file (same inode, §18.7), truncate, fsync.

Comments other than the header, tombstones, superseded rows, checksum markers,
and custom markers are dropped (§19.6).

### 5.8 Clear (single file)

`clear()`, `clear_file()`, `clearTabularFile`, and CLI `clear` rewrite the part
in place with the header comment followed by the active non-default markers and
`#_defaults_#` (§19.8). 3.39 dropped the defaults line. The read that finds the
header and markers uses the same optimistic check as §5.7: the rewrite happens
under the write locks only if the part is unchanged since the read; otherwise
clear reads again (so a record committed meanwhile is cleared too and a marker
committed meanwhile is kept), and after 3 changed attempts it gives up with a
warning and writes nothing. `TSVZed` commits its queue before clearing, so a
marker it queued (for example a new `#_defaults_#`) is part of the state that
clear keeps; if that commit fails, clear writes nothing, reports it, and marks
the store for a reload once writes recover.

## 6. API and CLI

- **No 3.39 name is removed or renamed**, and nothing emits a deprecation
  warning. New: the `dialect` attribute. `get_delimiter` maps strict
  extensions.
- **`TSVZed.__missing__`** (spec dialect): returns `[key] + defaults[1:]`,
  padded with `''` to `W`, while `#_return_defaults_when_missing_#` is true;
  else raises `KeyError`. Nothing is inserted. Legacy: raises `KeyError`.
  `in`, `get`, `setdefault`, and `pop` do not call `__missing__` and keep dict
  semantics.
- **`TSVZedLite`** (spec dialect): `__getitem__` applies the same rule.
  `__contains__`, `get`, and `setdefault` are overridden to consult the index,
  because the `MutableMapping` mixins would otherwise report missing keys as
  present. `pop(k, ...)` keeps its 3.39 meaning (return the defaults).
- **Stateless helpers** (spec dialect): `appendLinesTabularFile` writes rows as
  given (§5.2); `readTabularFile` reads all parts; `clearTabularFile` keeps the
  header comment and markers; `scrubTabularFile` is the archival scrub.
- **CLI**: operations `read`, `append`, `delete`, `clear`, `scrub` and flags
  `-d -c --defaults -s -f -v -V` are unchanged. On a `.tsvz` store `read`
  covers all parts, `delete` writes a lone tombstone, and `scrub` is the
  archival scrub.

## 7. Reporting

Covered by §2.2. Every tolerance event in §3.2, §4.9, §5.4–§5.6 is reported
through the reporter, once per kind per operation, with a count and first line
number where they apply.

## 8. Testing

`TSVZ_test.py`, plain pytest `test_*` functions.

1. **3.39 regression.** The 14 tests of `test_TSVZ.py`, ported to
   `import TSVZ`, pass with assertions unchanged.
2. **Legacy differential.** A seeded random operation sequence (set, delete,
   lone key, defaults, header, clear, scrub, reload; values containing the
   delimiter, `\n`, `<sep>`, `</sep/>`, `#…`, `<`) runs on twin files through
   `TSVZ_old` and `TSVZ` for `.tsv/.csv/.nsv/.psv` and `.tsv.gz`, via `TSVZed`,
   `TSVZedLite`, and the stateless helpers. File bytes and read results must be
   identical. The L1–L3 cases are excluded and tested on their own.
3. **Spec conformance.** At least one test per normative rule through the
   public API: Appendix C; §4 commit, CRLF, torn tail; §6 versions; §7
   classification; §8.4 empty key; §9 tombstones; §10 stripping; §11 comments;
   §12 statefulness, reset, case-insensitivity; §13 round-trip in all four
   variants including NUL; §14 binding, fill-empty, missing keys; §15 arming,
   verify, mismatch, cross-part segments, self-exclusion; §16 codecs; §17 hex
   ordering (`.f` before `.10`), part 0, `.rotated`; §19.4 scrub fidelity with
   markers changed mid-file.
4. **Tolerance.** Every row of the §4.9 table yields the kept data and exactly
   one summarised warning (stderr captured). Torn-tail truncation on an
   uncompressed part and on a gzip member; rewrite features on `.tsvz` warn and
   write nothing; delimiter conflict; direct part path.
5. **API.** `__missing__`; `TSVZedLite` `__contains__` / `get` / `setdefault`;
   `#` keys; reserved marker keys; `dialect`.
6. **Round-trip fuzz.** Seeded random Unicode values (including `<`, each
   delimiter, `\n`, `#`, embedded `\r`): write, reload, and scrub then reload
   give back the input, in both dialects. No new dependency.
7. **CLI.** Every operation via `subprocess`.
8. **Environments.** Current Python 3; Python 3.6 and 3.7 in Docker
   (`python:3.6-slim`, `pytest<7.1`, also with `LANG=C LC_ALL=C`). `.zst`
   tests skip below 3.14.
9. **Performance.** `benchTSVZ.py` on 100k rows, 3.39 against 4.1 on `.tsv`.
   Legacy-dialect load time stays within about 15% of 3.39.

## 9. Breaking changes from 3.39

### `.tsv`, `.csv`, `.nsv`, `.psv` (bug fixes only)

| # | Change |
|---|---|
| L1 | An append after an unterminated last line writes `\n` first; 3.39 merged the two lines. |
| L2 | An all-empty row set through the API is a delete in memory too, with a warning. |
| L3 | `TSVZedLite` on a compressed file holds rows in memory; 3.39 read compressed bytes as text. Index entries that hold a row are returned directly (3.39 crashed on them, e.g. for `#` keys). |
| L4 | New tolerance warnings on stderr; data unchanged. |
| L5 | A damaged compressed `.tsv.gz` (etc.) is read up to the damage with a warning; 3.39 raised `EOFError` / `zlib.error`. |
| L6 | `mapToFile` writes the row it adds at the end of the file with its `\n`; 3.39 omitted it and glued that row to the next one (e.g. `k2\tp\tqk3\tr\ts`), reproduced with `rewrite_on_exit=True` after a same-length in-place update. |

### `.tsvz`, `.csvz`, `.nsvz`, `.psvz` (now spec v1)

| # | Change |
|---|---|
| S1 | `.csvz/.nsvz/.psvz` infer `, \0 \|` (3.39: tab). A conflicting explicit `delimiter=` or `encoding=` is overridden, with a warning. |
| S2 | A file written by 3.39 reads differently: a plain header line is a data key; `key\t\t` deletes resurrect; `</sep/>` stays literal; literal `<lt>` / `<#>` text is decoded; an unterminated last line is dropped; single-column files read as empty; present-empty cells are not defaulted; only trailing space/tab is stripped; NULs are not stripped. Rename such files to `.tsv` to keep 3.39 behaviour. |
| S3 | `t[missing]` returns the defaults row instead of raising `KeyError` while `#_return_defaults_when_missing_#` is true (its default). |
| S4 | `#` keys persist as `<#>key` (3.39: memory-only). Keys matching `#_x_#` are marker writes. |
| S5 | Rewrite features warn and do nothing; `rewrite_on_load` effectively defaults to `False`; `move_to_end` reorders memory only. |
| S6 | No width trimming or dropping: wide rows are kept on read, wide values are kept on write, `appendLinesTabularFile` does not pad to header width, `strict` no longer drops rows. |
| S7 | The header is written as a `#` comment; a new file without a header is 0 bytes (3.39 wrote `\n`). |
| S8 | An unterminated tail is ignored on read and truncated on append; damaged compressed members are truncated. |
| S9 | `clear` keeps the active markers (3.39 dropped the defaults line). Scrub keeps the header comment and drops other comments, custom markers, and checksum markers. |
| S10 | Siblings named `x.tsvz.<hex>` are read as parts of the store. |
| S11 | `lastLineOnly` reads forward and is slower on large files. |

## 10. Spec deviations and interpretations (documented in the README)

- **§19.2.3c** — scrub keeps the header comment (3.39 header verification
  needs it).
- **§17.5** — a numbered part opened directly is read alone, with a warning.
- **§4.1** — a leading BOM is tolerated on read (stripped, warned).
- **§12.4.1** — boolean aliases `yes/no/on/off/1/0` are accepted on read;
  writers emit `true`/`false`.
- **§14.5** — the defaults-on-missing read applies to `t[key]`; `get`, `in`,
  `setdefault` keep dict semantics.
- **§18.6** — locking is 3.39's exclusive `lockf` per write, not the
  access/append lock pair (a SHOULD). Readers do not lock.
- **§19.4** — the compensating scrub layout re-emits markers after the rows;
  markers are valid anywhere, so this is an interpretation, not a deviation.
- Invalid UTF-8 is replaced with U+FFFD and warned about.

## 11. Out of scope

Writing multi-part stores, `snapshot_store`, `#_rotate_#` actions, promotion,
OFD access/append locks, `#_write_ack_#` behaviour, writing checksum markers,
MarkerWatch, `crc32c` / `blake3` digests, a `.tsv` → `.tsvz` migration command,
and any change to `tsvz-spec-v1.md`.
